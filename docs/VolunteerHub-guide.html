VolunteerHub team guide

A volunteering board for cultural institutions, festivals and associations. Organisations post the events that need volunteers, volunteers browse and save them, and an administrator keeps the board clean. Applications happen on the organiser's own website.

Repo EdonFa/Volunteer-Hub Current phase 1 · domain + web service Phase 1 due Sun 15 Nov 2026, 23:59 Guide updated 9 Nov 2026
Guest

Browses without an account

Searches events by category, city and dates, opens an event and follows the link to apply.

Volunteer

Finds an opportunity

Sets preferences, gets recommendations, saves events, checks the weather, applies on the organiser's site.

Organisation

Posts what it needs

Posts events, edits them, closes the recruitment when the event is full.

Administrator

Moderates the board

Accepts or refuses new events, removes events, suspends or removes accounts.

One rule shapes the whole platform: an event is invisible to the public until an administrator accepts it. Every new or edited event goes back to PENDING.

    Who checks what

    The most useful idea to understand the code. When you add a rule, this table tells you where it goes.

    LayerResponsible forExamples in our code
    DomainRules about one objectend date not before start date · only a PENDING event can be accepted · only a PUBLISHED event can be closed · volunteers needed > 0
    ApplicationStateRules that need all objectsunique usernames and organisation names · the category must exist in the catalogue · deleting an event also removes it from every volunteer's saved events · remove an account
    ResourcesTranslating HTTP onlyread the URL and the JSON body, call one ApplicationState method, return the object or a status code
    Exception mapperTurning errors into HTTP answersIllegalArgumentException → 400 · IllegalStateException → 409 · unknown id → 404

    One request from end to end

    Marie (Lausanne Jazz Association) posts a new event: POST /VolunteerHubService/api/events.

    #WhereWhat happens
    1PostmanSends the event as JSON, with Marie's organisationId.
    2Payara@ApplicationPath("/api") → @Path("/events") → the method annotated @POST in EventResource.
    3JSON-BCreates an empty Event and calls one setter per JSON property. setStartDate/setEndDate already check the period.
    4EventResourceCalls state.addEvent(event) on the injected ApplicationState.
    5ApplicationStateChecks the data, finds the organisation (not suspended), checks the date is not in the past, swaps the category for the catalogue one, gives a new UUID.
    6DomainOrganisation.addEvent links the event to Marie and sets it to PENDING.
    7EventResourceAnswers 201 Created with a Location header and the event as JSON. If a rule fails: 400 / 403 / 404 / 409 with a message.

    07 · service layer · VolunteerHubService

    What the service adds around the domain

    Built like StudyBuddyService. Two packages: rest is the door (HTTP ⇄ Java), service is the memory and the global rules.

    Inside ApplicationState

    The maps are the in-memory "database" of phase 1. Phase 3 replaces them with MySQL through JPA.

    FieldKey → valueUsed for
    organisationsUUID → OrganisationCRUD of organisations, owner of each event
    volunteersUUID → VolunteerCRUD of volunteers, saved events
    administratorsUUID → Administratorwho performs a moderation action
    eventsUUID → Eventfast lookup of any event, filters
    usernamesusername (lower case) → UUIDunique usernames, login
    organisationNamesname (lower case) → UUIDunique organisation names
    categoriestitle (lower case) → Categorythe catalogue; "music" and "Music" are the same
    Three annotations do the invisible work. @ApplicationScoped: one shared instance for the whole server. @Inject: every resource gets that instance. @PostConstruct: init() runs once at start-up and loads the demo data. The methods are synchronized because requests can arrive at the same time.

    09 · run & test

    From a fresh clone to a running service

    Needs Java 17, IntelliJ, Docker Desktop and Postman (How-to chapter 1).

    1. Get the code

      IntelliJ → Clone Repository → https://github.com/EdonFa/Volunteer-Hub.git. Check the branch in the top-left corner.

    2. Install the domain

      Maven tab → VolunteerHubDomain → Lifecycle → clean, then install. The 56 tests run on the way. Do it again after every change in the domain.

    3. Package the service

      Maven tab → VolunteerHubService → Lifecycle → clean, then package. It creates target/VolunteerHubService.war. Not in the Maven tab? Right-click its pom.xml → Add as Maven Project.

    4. Start it in Docker

      Docker Desktop must be running. In a terminal, from the VolunteerHubService folder:

      docker build -t volunteerhub-service .
docker run --rm --name volunteerhub -p 8080:8080 volunteerhub-service

      Ready when http://localhost:8080/VolunteerHubService/ shows "Successfully Deployed" (about 10 s). Course method also works: copy the war into StudyBuddyDocker/deployments and run docker compose up -d there. Only one Payara at a time: both use port 8080.

    5. Test in Postman

      Import VolunteerHubService/postman/VolunteerHub.postman_collection.json. Send 0 · Setup / Reset demo data, then the folders in order, or right-click the collection → Run collection: 43 green tests.

    10 · how we work

    A small framework for the group

    The same workflow as the course video 9.2: main stays stable, everyone works on a branch, a teammate reviews before merging.

    Git workflow

    1. Pull main, create a branch named after the task (service, webapp-login, jpa-event)
    2. Commit small steps with a clear message
    3. Before pushing: domain tests green, Postman collection green
    4. Push, open a pull request into main
    5. One teammate reads it and approves, then merge

    Adding a feature, in order

    1. Domain: method + JUnit test (if it is about one object)
    2. ApplicationState: method with the global checks
    3. Resource: one annotated method that calls it
    4. Postman: one request in the collection, re-export it
    5. README: a line in the coding session

    Rebuild order

    Domain changed → install the domain, then package the service, then rebuild the Docker image. Service changed → package + rebuild only. Restarting a container is not rebuilding it.

    Conventions

    • Code, comments and READMEs in English
    • Each work session adds a Coding session dd.mm block to the README: what we did, things to know, next tasks
    • Never commit target/, .idea/ or .DS_Store (already in .gitignore)
    • Use the demo ids in Postman, never random ones
    Every member must understand the whole project, not only their part: the professor asks questions during the demos, and the video requires everybody to explain what they did.

    Questions the professor may ask

    Why two separate projects, domain and service?

    Separation of concerns. The domain holds the business rules and can be tested without a server; the service only exposes it over HTTP. The web app (phase 2) and JPA (phase 3) reuse the same domain.

    How do the HTTP verbs map to CRUD?

    POST creates, GET reads, PUT updates, DELETE deletes. /events is the collection resource, /events/{id} one item.

    What do @ApplicationScoped and @Inject do?

    The server creates one ApplicationState for the whole application and injects that same instance into every resource. Without it, each resource would see different data.

    What happens to the data when the container restarts?

    It is lost and the demo data is loaded again, because everything is in memory. Phase 3 adds persistence with JPA and MySQL.

    How does a Java object become JSON?

    JSON-B uses the getters to write JSON, and the empty constructor plus the setters to read it. That is why we added single-date setters and list setters to the domain.

    Why is the unique username check in the service and not in the domain?

    A single User object does not know the other users. The rule needs the list of all users, which only ApplicationState has.

    Why does Event override equals and hashCode?

    An event received as JSON is a new Java object. Equality on eventId (like Topic on its title in StudyBuddy) lets a Set recognise it. Equal objects must have equal hash codes, otherwise HashSet and HashMap break.

    Your project description mentions volunteers still needed and time slots. Where are they?

    The group dropped volunteers still needed: an organisation closes the recruitment when the event is full. Time slots: see the decision in section 11.

    What does the external API bring?

    Volunteers see the forecast for the city and dates of an event. Our service is itself a client of Open-Meteo (geocoding then forecast), with the JAX-RS client API from the course.
